ブログページの分析
C:\Users\creje\blog_analytics

① 仮想環境を有効化

Windows（コマンドプロンプト）の場合：

.venv\Scripts\activate

成功すると、

コマンドの先頭が

(.venv) C:\workspace\blog_analytics>

のようになります。

② コマンドプロンプトでそのフォルダへ移動

例：

cd C:\Users\creje\blog_analytics\scripts


③ 認証スクリプトを実行
python auth_gsc.py

すると、

Please visit this URL to authorize this application:
https://accounts.google.com/...

のようなURLが表示されるか、自動でブラウザが開きます。

④ Googleアカウントでログイン

GSC・GA4のプロパティにアクセス権限のあるGoogleアカウントでログインします。

GSCとGA4を両方選択しつつ、続行を数回選択

「このアプリは確認されていません」と表示された場合は、以前と同じように

詳細
（安全ではないページ）に移動
許可

を選択すればOKです（テストユーザーとして登録済みであれば利用できます）。

⑤ 認証完了

認証が終わると、プロジェクトフォルダ内に

token.json

または

token.pickle

（スクリプトによって名前は異なります）

が作成されます。

以後は

python fetch_gsc_daily.py
python fetch_ga4_daily.py

を実行するだけでデータを取得できます。

⑥仮想環境の無効化
deactivate

そして、

python fetch_all.py

を実行すればすべてのGSC及びGA4ファイルの更新が完了する仕組み


例えば30日分取得したいなら、

python fetch_gsc_daily.py 30

と実行します。

GA4も同様に、

python fetch_ga4_daily.py 30

となります。

なお、引数がなければ600日分のデータを取得

※実質的に取得可能な全期間分

最後に、

python merge_daily.py

を実行して、GA4とGSCデータを結合（日付指定なし）

Search Console APIとGA4 APIは別々にデータを取得し、最後に merge_daily.py で結合しています。

GA4は14か月、GSCは16か月までデータをさかのぼってAPI保存可能


csvデータを取得したら、
C:\Users\creje\blog_analytics\data\daily内にある以下のファイルをエクセルで加工して分析
daily_performance,csv
ga4_page_daily.csv
merged_daily.csv

| ファイル                        | 役割                          | どんな時に実行・出力するといいか                                          |
| --------------------------- | --------------------------- | --------------------------------------------------------- |
| **analyze_gsc.py**          | GSCデータを分析する                 | GSCの検索パフォーマンスを個別に分析したいとき                                  |
| **auth_gsc.py**             | GSC APIの認証を行う               | **通常は単独実行不要**。GSC APIを利用するスクリプトから呼び出すための認証処理              |
| **build_duckdb.py**         | CSV等をDuckDBに取り込んでDBを構築・更新する | GSC・GA4のCSVを更新した後、**DuckDBで分析したいとき**                      |
| **fetch_ga4_channel.py**    | GA4の流入チャネル別データを取得する         | 「Organic Search / Direct / Socialなど、どこからアクセスされたか」を分析したいとき |
| **fetch_ga4_daily.py**      | GA4の日別データを取得する              | **日ごとのユーザー・ビュー・セッション等の推移**を分析したいとき                        |
| **fetch_gsc_daily.py**      | GSCの日別データを取得する              | **日ごとのクリック・インプレッション等の推移**を分析したいとき                         |
| **fetch_gsc_page.py**       | GSCのページ（記事）別データを取得する        | **どの記事がアクセスを稼いでいるか**を分析したいとき                              |
| **fetch_gsc_query.py**      | GSCの検索クエリ別データを取得する          | **どんな検索ワードでブログが表示・クリックされているか**を調べたいとき                     |
| **fetch_gsc_query_page.py** | 「検索クエリ × ページ」別データを取得する      | **どの検索ワードから、どの記事に来ているか**を詳しく調べたいとき                        |
| **get_date_range.py**       | APIから取得する期間を設定する            | 他の取得スクリプトで**取得期間を変更したいとき**                                |
| **merge_daily.py**          | GSC・GA4の日次データを統合する          | **GSCとGA4を日別で比較・統合分析したいとき**                               |
| **sql_analysis.py**         | DuckDBにSQLを実行して分析する         | DuckDBに蓄積したデータから**定型的な分析結果を作りたいとき**                       |
| **update_all.py**           | データ取得・DB更新・分析等をまとめて実行する司令塔  | **最新データへの更新を一通りまとめて行いたいとき** update_gsc,build_duckdb,sql_analysisを実行|
| **update_gsc.py**           | GSC関連データの取得・更新をまとめて行う       | **GSCだけ最新データに更新したいとき** daily,page,query,query_page                                    |
| ****pycache****             | Pythonが自動生成するキャッシュ          | **自分で実行する必要なし**。Pythonが自動的に作成・利用する                        |
